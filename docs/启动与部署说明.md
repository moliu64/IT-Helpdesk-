# IT 运维工单智能体：启动与部署说明

## Windows 唯一入口

项目只保留一个用户启动/部署入口：双击 `项目控制面板.bat`。控制面板内提供“一键启动项目”“停止项目”“打开网站”三个中文按钮，统一管理本机源站和 Cloudflare Tunnel。面板以无控制台窗口方式运行，不会残留闪烁的终端窗口；“停止项目”在后台异步执行，面板保持可操作、可随时关闭，关闭面板本身不会停止服务。

启动后：

- 用户入口：`http://127.0.0.1:8787/`
- 后台管理入口：`http://127.0.0.1:8787/backend`，兼容 `http://127.0.0.1:8787/admin`
- RAG 知识库管理页：`http://127.0.0.1:8787/rag`（后台 RAG 区域点击「管理 RAG 知识库」在新标签页打开；按文档管理知识条，支持单条增删改迁、上传自动解析并重建索引）
- 健康检查：`http://127.0.0.1:8787/healthz`

首次运行部署脚本会自动创建 `.venv` 并安装 `requirements.txt`，之后直接复用现有环境。部署脚本会先等待 `http://127.0.0.1:8787/healthz` 成功，再启动 Tunnel；日志位于 `output/`。可使用 `-NoBrowser` 禁止自动打开浏览器，`-SkipInstall` 跳过依赖安装。脚本默认设置 `HF_HUB_OFFLINE=1` 和 `TRANSFORMERS_OFFLINE=1`，模型需预先缓存在本机。

当前 Windows 主机已经配置好 Cloudflare Tunnel 时，双击 `项目控制面板.bat` 即可打开中文控制面板。面板会启动 Python 源站和 Tunnel 的独立后台进程；关闭 CMD 或控制面板窗口不会停止服务。需要停止时点击“停止项目”。线上地址默认为 `https://060115.top/`，日志写入 `output/online-app.log`、`output/online-app.err`、`output/cloudflared.log`、`output/cloudflared.err`、`output/control-panel.log` 和 `output/control-panel.err`。需要自定义地址或路径时，可在 `.env` 设置 `HELPDESK_PUBLIC_URL`、`HELPDESK_TUNNEL_CONFIG` 和 `CLOUDFLARED_PATH`；自定义端口使用 `HELPDESK_ONLINE_PORT`。修改 `.ps1` 启动脚本时保持 UTF-8 带 BOM，修改 `.bat` 时保持 CRLF 换行，否则 PowerShell/cmd 会出现中文乱码或拆行报错。

### cloudflared 查找与自愈

`start_online.ps1` 不再只依赖 PATH。它按以下顺序查找 `cloudflared.exe`：`.env` 中的 `CLOUDFLARED_PATH` → `PATH` → `%USERPROFILE%\.cloudflared\cloudflared.exe` → `deploy/060115.top/cloudflared.exe` → `Program Files` 下的两个默认目录 → WinGet 安装目录。全部找不到时会自动从 Cloudflare 官方发布页下载到 `%USERPROFILE%\.cloudflared\cloudflared.exe`（无需管理员权限）；离线环境可先手工放置该文件，或用 `-SkipTunnelDownload` 关闭自动下载。

启动时脚本还会校验 Tunnel 配置文件里的 `credentials-file` 是否存在、`service` 端口是否与本机源站一致，并在 Tunnel 真正注册到 Cloudflare 边缘节点后才报告“已部署上线”；结束后还会再请求一次公网 `/healthz`，公网未通会给出黄色警告而不是假装成功。

### 面板显示启动失败原因

控制面板启动失败时不再只提示“请查看日志”，而是把 `output/control-panel.err` 与 `output/control-panel.log` 的最后几行直接显示在面板日志区和弹窗中。面板也会先读取 `.env`，确保探测端口与 `start_online.ps1` 使用的端口一致。

### 脚本编码要求（重要）

`项目控制面板.ps1`、`start_online.ps1`、`stop.ps1` 必须保存为 **UTF-8 带 BOM**。Windows PowerShell 5.1 在没有 BOM 时会按系统 ANSI 代码页（本机为 GBK/936）解码脚本文件，中文注释与字符串会被读成乱码，轻则界面文字变乱、重则直接报“字符串缺少终止符”而无法运行。用代码编辑器修改这些脚本后，请确认保存编码仍为“UTF-8 带 BOM”。

`项目控制面板.ps1`、`start_online.ps1` 和 `stop.ps1` 是面板内部实现脚本，不作为日常启动入口。

启动脚本会把实际监听端口的 Python 进程 PID 写入 `output/online-app.pid`，而不是只记录 Windows 虚拟环境启动器 PID，避免停止后残留服务。

控制面板使用 Windows PowerShell 5 兼容写法；如果系统策略阻止脚本运行，入口已带 `-ExecutionPolicy Bypass`，仍需确保 Windows Forms 可用。

## 060115.top 部署入口

线上部署模板位于 `deploy/060115.top/`，包括 Nginx 反向代理、systemd 服务和 Docker Compose 两种方式。建议由 Nginx 负责 HTTPS 和域名，再转发到本机 `8787` 端口；后台认证由应用自身的 `/login` 登录页 + Cookie 会话完成，Nginx 层的 Basic Auth 仅作为可选的额外防护。

发布前需要：

1. 将 `060115.top` 和 `www.060115.top` 的 DNS A 记录指向服务器公网 IP。
2. 在服务器安装 Python 3.10+、Nginx，并配置 `LLM_API_KEY` 环境变量。
3. 复制 `deploy/060115.top/.env.example` 为服务器上的 `.env`，不要提交真实密钥。
4. 按 `deploy/060115.top/README.md` 配置 HTTPS 证书和后台认证。

后台包含工单、知识库、运行日志和访问记录。启动前请在 `.env` 设置 `HELPDESK_ADMIN_USER`、`HELPDESK_ADMIN_PASSWORD` 和稳定的 `HELPDESK_SESSION_SECRET`；未登录访问 `/backend` 会跳转到 `/login` 登录页，登录成功后由 HttpOnly 签名 Cookie 保持状态（默认 30 天，可用 `HELPDESK_ADMIN_SESSION_DAYS` 调整），不会弹浏览器原生身份验证框。后台和管理 API 不能在没有认证的情况下直接暴露公网。
